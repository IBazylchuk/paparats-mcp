The call graph follows the class a call is made on. A call on a variable or a field links to its class's method when the file shows the class: `x = Report.new(...)`, `plan = Plan.find_by(...)`, `@client ||= Api::Client.new`, a method or `attr_reader` returning one, a constant holding one; in TypeScript a type annotation, `new`, a field, a constructor parameter property or a function's declared return type. The method is looked up the class's ancestry (superclass, `include` / `extend` / `prepend`, `extends` / `implements`), then in the classes below it (an interface's implementations, a mixin's hosts). A call on a builtin, a Node module, an installed package, or a class that defines no such method anywhere up or down its ancestry links to nothing, instead of to whatever else has the name. In TypeScript and JavaScript an imported name links to the module it comes from, names read as values (`retry(fetchPage)`, a constant) are uses, and a call through `await x.f<T>()` is no longer missed; the project's own packages and tsconfig path aliases are read from its `package.json` and `tsconfig*.json` files. A class added, removed or re-parented rebuilds the whole graph; whether a name is common is now counted over every file using it, linked or not.

Checked against the TypeScript compiler on this repository's server, for edges through names `change_impact` does not set aside as common: 92.6% of edges are real (86.9% before) and 97.7% of the real ones are found, import lines aside (76.3% before); on a private TypeScript codebase 99.8% (98.9%) and 99.9% (72.6%). On a private Ruby codebase, over 300 targets, 106 direct callers are no longer linked, and none of the 56 checked blind against the code was real; class-method callers against grep: 98.3% of found callers real (95.7% before), 26.5% of them found (26.6%). Symbols are extracted again once on the next pass.
